Values are synthetic-plan-equal mean rigid errors in **mm**. The true-key/CCF rows are oracle conditions: a deployable model cannot see those coordinates. Across the relevant v4 near subset, every one of 18,567 valid 24×24 query sites had a supported atlas key within the model's 3-mm locality; only 59 sites had their nearest key farther than the trainer's 0.9-mm positive-label radius. On exact v4 cases, all 21,499 queries had a supported local key (132 beyond 0.9 mm). Thus absent atlas support or the finite key grid is not the dominant limit in this panel. The true-key plus ideal-weight result differs from continuous truth by only 0.007 mm on v4 near cases and 0.024 mm on exact cases.

The learned expected correspondence and learned confidence both matter. On v4 near cases, replacing the expected map with the true nearest key while *retaining* learned weights improves 0.807→0.662 mm; replacing those weights with ideal tissue-validity weights improves further to 0.532 mm. Exact-plane error likewise falls from 0.377 to 0.104 mm under the weight replacement, though soft learned expectations happen to outperform hard true-key matches when both use the flawed learned weights (0.339 vs 0.377). These differences identify bottlenecks in matching and weighting together; they do not prove which network component or loss causes either error. Ideal continuous correspondence still leaves 0.525 mm on v4 near branches, versus 0.510 mm for rigid truth: local deformation is a smaller contributor. The remaining large residual is from the unchanged, conservative ridge solve and the geometry of these actual candidate errors. Its ideal 0.837→0.525 mm gain only barely exceeds the prespecified 0.30-mm 148 threshold, so simply increasing unchanged training or atlas-key resolution is not a credible next step.

**Decision:** 148 remains rejected. The next development change should improve cross-domain anatomical correspondence and train a spatially well-distributed, correspondence-reliability-aware fit, while setting the plane trust/ridge using TRAIN-only data. Use a new held-out synthetic-plan panel to test this change rather than repeatedly optimizing on these already-examined DEV sections. Preserve real-image guardrails, independent per-section generator draws and full-sphere orientation support; do not unfreeze the 132 pose head or promote any GUI model until a genuinely discriminative post-fit pose signal is shown. This oracle says nothing about physical steep-oblique accuracy, calibration, electrode-region probabilities or DeepSlice superiority.
