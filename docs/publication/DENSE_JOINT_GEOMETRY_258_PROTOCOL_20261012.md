# 258: make dense correspondence, not the failed anchor head, produce the plane

The frozen 257 assay found support-matched true-pose atlas appearance beats local wrong poses across centre, tilt, roll, span and shear on the actual v7 DEV images. Yet 256's image-selected 64-anchor pose is 4.773 mm off and its best available branch is 2.156 mm off. Another scalar selector cannot create near-true branches. The earlier 075 dense auxiliary learned pixel coordinates but did not improve the unchanged anchor-selected pose; this intervention makes the spatial map itself the source of the pose.

Instantiate the existing `OneShotJointSliceModel` from fresh random initialization with its 96×96 dense CCF-coordinate/validity head as the only trained geometric output (`modes=0`, no normal anchors; unused atlas scorer/refiner/warp remain random and are not claimed). On each **independently drawn** eligible 192-pixel full-sphere v7 TRAIN section, directly supervise each surviving pixel's observed-tissue-to-CCF AP/DV/ML coordinate in millimetres, plus a class-balanced tissue-correspondence validity logit. A differentiable validity-weighted least-squares fit of this predicted coordinate map to an image plane provides global centre, orientation, roll, span and shear; the coordinate-map residual about that plane represents local deformation, including independently mapped surviving tear fragments. There are no paired appearances, reused physical sections, pretrained weights/features/pseudolabels, real weak labels, or CAL/FINAL/public benchmark examples.

Run a bounded 5,000 batches of four eligible independently drawn sections (20,000 presentations), with checkpoints at batches 0/1,000/3,000/5,000. The first 1,000 batches train dense CCF coordinates and validity; thereafter add `0.5 ×` the fitted plane's surviving-tissue rigid coordinate error in mm. Use AdamW `1e-4`, weight decay `1e-4`, global gradient clip 5; log each batch, all accepted/rejected draw identities, exact source/protocol hashes, RNG/optimizer state and checkpoint hashes on I:. This is a pose-capture/representation gate, not a finished joint probabilistic model. The local residual, uncertainty and fitting-difficulty feedback need subsequent full-model training if the plane capture succeeds.

Evaluate only the frozen 248 panel at the three trained checkpoints, retaining all 227 eligible cases and eight synthetic-plan identities. Report equal-plan fitted-plane rigid coordinate and normal-axis errors, dense valid-pixel coordinate error, validity Dice, appearance and cut-angle strata, and comparison with 247/254/256 on the same cases. Select the checkpoint with the lowest equal-plan fitted-plane rigid error, fixed before readout. Continue this lineage only if its best checkpoint has ≤3.8 mm fitted-plane error, ≤3.0 mm dense correspondence error, and beats 256's selected rigid error in at least six of eight plans. These are development continuation thresholds, not GUI, biological, calibration or benchmark gates. If it fails, investigate whether dense coordinate regression generalizes before adding refinement, candidate ranking or more exposure unchanged.

The design is analogous to [dense scene-coordinate regression followed by geometric pose fitting](https://openaccess.thecvf.com/content_cvpr_2017/html/Brachmann_DSAC_-_Differentiable_CVPR_2017_paper.html), and directly contrasts with [DeepSlice's global O/U/V corner-vector prediction on coronal sections](https://www.nature.com/articles/s41467-023-41645-4). Neither paper demonstrates success on this particular single-section, arbitrary-plane, tearing-prone problem; the frozen synthetic and later animal-separated gates must decide that.
