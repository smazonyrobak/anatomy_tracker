# AIND 568105: exact registered-grid identity is not recoverable from public metadata alone

The [bounded image QC](AIND_SMARTSPIM_568105_ORIENTATION_QC_20261012.md) establishes the gross `[ML,DV,AP]` array permutation and AP/DV signs at 200 µm, but not ML chirality or exact 25-µm origin. This follow-up inspected only metadata, source code, and 64-KB HTTP ranges of transform **headers**; no full volume/transform, model, GPU, or 287 output was read. The answer is still **no**: the published 568105 asset does not bind its fixed TIFF's signed voxel-center coordinates to this project's pinned CCF frame.

Evidence chain:

1. The run's [registration processing record](https://aind-open-data.s3.us-west-2.amazonaws.com/SmartSPIM_568105_2024-03-06_10-19-06_stitched_2024-03-08_03-13-28/image_atlas_alignment/Ex_639_Em_667/metadata/processing.json) names `aind-ccf-registration` v0.0.17 / ANTsPy 0.4.2, `orientations={left_to_right:0, superior_to_inferior:1, anterior_to_posterior:2}`, 25-µm requested output, and fixed image `/tmp/nxf.XwU7VHFn6r/capsule/data/ccf_atlas_image/ccf_atlas_reference_25_um.tiff`. It provides neither that TIFF's SHA-256 nor its signed index-to-CCF affine/voxel-center convention.
2. [v0.0.17 `main.py`](https://github.com/AllenNeuralDynamics/aind-smartspim-ccf-registration/blob/v0.0.17/code/main.py#L128-L211) takes acquisition `axes` for the **moving** image and supplies the TIFF path plus the axis-name map. [v0.0.17 `check_orientation`](https://github.com/AllenNeuralDynamics/aind-smartspim-ccf-registration/blob/v0.0.17/code/aind_ccf_reg/utils.py#L154-L208) reorders/flips that moving array. Neither establishes how the fixed TIFF was made from the Allen reference; its docstring even lists axes in an order different from `main.py`'s executable mapping, so the processing parameters/code path, not the prose comment, are authoritative.
3. [v0.0.17 `atlas_alignment`](https://github.com/AllenNeuralDynamics/aind-smartspim-ccf-registration/blob/v0.0.17/code/aind_ccf_reg/register.py#L257-L331) loads that fixed TIFF via `ants.image_read`, registers to it, and returns `reg12['warpedmovout'].numpy()` directly. The [Zarr writer call](https://github.com/AllenNeuralDynamics/aind-smartspim-ccf-registration/blob/v0.0.17/code/aind_ccf_reg/register.py#L385-L435) separately labels the output with `PhysicalPixelSizes(25,25,25)`. The [actual `.zattrs`](https://aind-open-data.s3.us-west-2.amazonaws.com/SmartSPIM_568105_2024-03-06_10-19-06_stitched_2024-03-08_03-13-28/image_atlas_alignment/Ex_639_Em_667/OMEZarr/image.zarr/.zattrs) stores only `z,y,x` plus scale, with no signed direction or translation.
4. The first 65,536 compressed bytes of each saved [forward](https://aind-open-data.s3.us-west-2.amazonaws.com/SmartSPIM_568105_2024-03-06_10-19-06_stitched_2024-03-08_03-13-28/image_atlas_alignment/Ex_639_Em_667/ccf_ls_warp_transforms.nii.gz) and [inverse](https://aind-open-data.s3.us-west-2.amazonaws.com/SmartSPIM_568105_2024-03-06_10-19-06_stitched_2024-03-08_03-13-28/image_atlas_alignment/Ex_639_Em_667/ls_ccf_warp_transforms.nii.gz) warp were fetched with HTTP `Range: bytes=0-65535` (206 Partial Content; SHA-256 of the ranges `90752db1606978e6492032fc5ca489372ee3f4bc10243eb4e3af5390934bc58c` and `71ca606bab8b96e788ef39d6db51d12e97c64bdfdf65a7d80ce2fa1c70b8a672`). Their gzip-decoded NIfTI-1 headers both report shape `456×320×528×1×3`, zooms `1,1,1` **mm**, origin `0`, and RAS sform diagonal `[-1,-1,+1]` (qform/sform code 1). These headers describe ANTs' index-like TIFF registration grid, not a 25-µm anatomical CCF frame; they cannot decide whether registered array index 0 is anatomical left or right, or whether CCF voxel centers coincide with Zarr integer indices.
5. This project pins `average_template_25.nrrd` SHA-256 `e4a2b483e842b4c8c1b5452d940ea59e14bc1ebaa38fe6a9c3bacac6db2a8f4b`, array shape `[AP,DV,ML]=[528,320,456]`, nominal origin 0 and + posterior/inferior/right at 25 µm in [`arbitrary_plane_allen_atlas_binding_v6.py`](../../training/arbitrary_plane_allen_atlas_binding_v6.py). Matching dimensions do not identify the fixed TIFF's signed voxel-center mapping to that frame. A contemporaneous [public pipeline revision](https://github.com/AllenNeuralDynamics/aind-smartspim-pipeline/blob/746557d43be56e4ca53dc051ad8188d74ebd29e8/pipeline/main.nf#L234-L269) points `ccf_atlas_image` to Code Ocean data asset `165a797d-cfca-420b-becc-0c89295ecf3f`, but the 568105 processing record does not authenticate that revision or asset bytes. The public [May 2024 SmartSPIM template asset](https://aind-open-data.s3.us-west-2.amazonaws.com/SmartSPIM-template_2024-05-16_11-26-14/README.md) postdates this March 2024 run and uses a different template-based workflow; it is not evidence that its CCF file equals the run's TIFF.

**Minimum missing evidence:** an authenticated, signed 4×4 map from registered Zarr spatial **voxel centers** `(z,y,x)` to this project's `[AP posterior,DV inferior,ML right]` micrometres, tied to the exact `ccf_atlas_reference_25_um.tiff` SHA-256/run asset. Equivalently, provide that exact TIFF with its construction/orientation manifest and an independent left/right asymmetric landmark plus a known voxel-origin correspondence. A TIFF header alone (often lacking anatomy directions), a warp filename, or a near-symmetric image-correlation advantage is insufficient. Until then, keep AIND data out of exact-coordinate supervised arbitrary-plane TRAIN rows; metadata/image-source exploration remains possible without coordinate claims.
