# 248: independent v7 synthetic DEV panel

After the 247 training run, freeze the separate 248 deformation-plan stage, then run `python -m training.prepare_one_shot_v7_heldout_dev_panel_248` from the repository root on I:. This CPU-only panel preparation does not load a model or choose a checkpoint. Do not use the panel for training, calibration, or a FINAL/public claim.

The script loads eight new development-only accepted 3D deformation plans (seed `2026101249`, indices `2000–2007`) and checks plan IDs, realization IDs, receipts, and local-field hashes against the 64 TRAIN bases, four earlier v6 DEV bases, and eight earlier eight-subject DEV cohorts. It bakes each plan's inverse on CPU with the v7 TRAIN interpolation and sampled `≤5 µm` accuracy rule. These are eight independent synthetic deformation realizations of the same pinned Allen atlas, **not** eight biological animals. Sixty-four affine variants per base follow the v7 size/aspect distribution but are not counted as independent anatomy.

For each base, 32 separately seeded planes are drawn at 192 px by the unchanged v7 geometry/appearance-v3 and one-shot artifact-v3/v4/v6/v7 sampler. One affine variant and one appearance/background/mode are drawn per plane; there are no paired appearances, tissue-based retries, or replacements. All 256 attempted planes are retained, including ineligible ones. The fixed source-support and observed-valid thresholds are each `192²/144`; the eligible count is a result, not a target of 185. The sampler's hard-coded `split=train` provenance label is changed to `development` only after sampling from DEV-only bases.

The output is `I:/AnatomyTracker/data/one_shot_v7_heldout_dev_panel_248_004`. Attempts `_001`–`_003` had native Windows access violations during the first deformation-plan draw and contain only `protocol.json`; none is a panel. The isolated first plan completed twice, but single-thread OpenBLAS and then 4,096-point B-spline chunking did not stabilize the full script. The chunk intervention is reverted. Plan generation is now a separate, resumable [frozen stage](ONE_SHOT_V7_HELDOUT_DEV_PLANS_248_PROTOCOL_20261012.md), and this panel script consumes only its eight completed, hashed plans. Two initial `_004` launches also suffered native access violations during historical-plan reading and atlas preprocessing, before any sections were made. Their protocol-only directories are preserved on I: with `_failed_20261012_0135` and `_failed_20261012_0139` suffixes; isolated replays of both operations passed, so the native failure remains unexplained. The builder now freezes each subject's 32 section records and hashes separately and can resume an exact completed subject after a crash. It stops, rather than silently replaces data, if a subject has partial files without its completion receipt. Seeds, plan identities and the deformation distribution are unchanged. `protocol.json` binds that plan stage, input manifests, TRAIN-only acquisition-framing geometry, pinned atlas, code hashes, seeds, and package versions. Each subject has its accepted plan, receipt, baked map, and mapping checks; each section NPZ has five-channel input, pose, dense observed-pixel CCF coordinates, valid mask, visible support, source support mass, reflection, PSF offsets/weights, and eligibility. `records.jsonl` holds physical-section, subject, variant, geometry, artifact, seed, and file hashes. Only global `completed.json` marks a fully frozen panel. The 247 evaluator is not changed and its 256-px assumptions do not apply to this 192-px panel; the separate 248 evaluator binds this manifest without checkpoint selection.

The only acquired-data dependency is the existing TRAIN acquisition-framing geometry used by v7; there are no CAL/FINAL donors or public benchmark sections. The map truth remains FP32 interpolated inverse coordinates with a sampled, not global, error certificate. This is a matched-simulator DEV diagnostic, not an independent biological or external validation set.
