# Balanced correspondence and pose continuation 033

032's all-17-way cross-entropy made “no match” dominant even where a correct atlas candidate was available. Continue **the same** randomly initialized selector, frozen project descriptor, atlas bank, optimizer and RNG state from its batch-3,000 checkpoint. Do not reset or splice in external weights. Draw 6,000 further batches of two fresh arbitrary-plane synthetic TRAIN sections each (12,000 new sections). Keep the identical architecture and 32 known-valid training query pixels per section, candidate retrieval and provenance logging.

Replace the single classification loss with three simultaneous terms: (1) conditional cross-entropy among the 16 candidates for queries whose nearest atlas point lies within 500 µm; (2) weighted binary cross-entropy for whether any true candidate exists, using fivefold positive weight; (3) Huber error of the model's differentiable weighted image-to-CCF plane fit against known synthetic query coordinates. This is supervised pose learning, **not yet atlas image-fitting feedback**. The conditional term prevents the no-match option from suppressing the only available inlier gradients. Keep AdamW at 1e-4, gradient clipping at 5 and no other architecture or data change. Freeze checkpoints after overall batches 3,000 (parent), 5,000, 7,000 and 9,000; retain the best DEV checkpoint rather than automatically taking the last.

Evaluate once on the same fixed synthetic DEV panel and 030 top-16 lists. The necessary gate is the same as 032: ≥50% correct selected among available queries, ≤20% false matches among unavailable queries and <2.5 mm rigid plane-fit mean. A pass allows the next integration step: replace training-only query selection, add atlas rendering and local fitting in the same model, and verify that **anatomical fitting loss changes the pose predictor in a direction that improves localization**. A failure calls for a different correspondence inductive bias or a direct global pose strategy, not another unchanged extension. No real calibration, GUI replacement, final-test animal or public benchmark is used here.
