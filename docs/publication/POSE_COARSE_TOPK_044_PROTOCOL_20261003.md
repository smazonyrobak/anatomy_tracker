# 044 pre-run decision test: can a fine matcher see a true atlas key?

The frozen 041 matcher and 043 consensus cannot yet deliver an accurate pose. Before building a more expensive fine-scale patch reranker, measure whether the 041 coarse logits actually place a physically correct atlas key in a tractable short list. A fine reranker cannot recover a key its coarse retriever omits.

At the frozen 041 batch-1,500 checkpoint, use exactly the original top eight 019 candidates on the unchanged 177 eligible synthetic development sections (eight disjoint synthetic deformation identities). For every visible 16×16 query cell, compare known synthetic tissue-to-CCF truth to all **supported** atlas keys (`support > 0.1`); count a key as correct within 1.5 mm. Report key-availability coverage and top-8/top-32/top-64 retrieval recall both conditional on availability and among all valid query cells, separately for the image-prior top-one and physically best-of-eight plane. Also count whether each section has correct top-64 keys in at least three distinct 8×8 chart quadrants, a simple spatial-span requirement for fitting a frame. Use truth only to score, never to choose retrieved keys.

A 025-like fine patch reranker is justified only if physically best-of-eight top-64 recall is ≥80% among available cells, image-prior top-one top-64 recall is ≥60% among available cells, and ≥80% of sections have three-quadrant coverage on the best candidate. Otherwise, fix coarse off-plane retrieval first with hard-negative training; do not merely enlarge the reranker or change the geometric fitter again. These thresholds choose the next development direction, not a deployment claim. No real weak labels, public benchmark, or final-test animal is used in this retrieval-ground-truth diagnosis.
