# 101: does the 099 descriptor improve the actual 094 fit and selection?

Freeze `training/diagnose_matcher_swap_101.py` before reading any 101 score. The experiment uses the existing identity-disjoint 099 synthetic DEV panel, but selects only the first eight eligible physical sections per each of its eight deformation plans (64 distinct sections). This is exploratory reuse of a DEV source already used for the 099 descriptor gate, **not** independent confirmation or real-animal validation.

Both arms receive identical images, frozen 094 encoder/predictor/mapper, finite-thickness atlas, top-eight plus top-six 14-branch beam, fit/correctness head, bounded pose correction, deformation head, and scoring formula. Swap only the embedded matcher between zero-initialized 099 step 0 and trained 099 step 4000. Require first-section numerical parity of step 0 with the original 094 fitter for match logits/support, fitted state, quality/coverage, mapped CCF, and selection score. Evaluate all 14 branches in both arms on the same 1,024 deterministic valid observed pixels per section.

Primary diagnostic: paired change in score-selected mapped 3-D visible-tissue error, with plan-equal means and individual-plan signs. Also report normal/centre error, physically best of the same fitted 14 branches, selection regret, fit quality/coverage, correction cost, support, and local-warp cost by plan and true normal family/obliquity. A gain in raw match accuracy alone does not count as a gain in alignment. The 099 descriptor should be integrated into further joint training only if actual score-selected physical error improves without simply allowing larger deformation or trading away the hard oblique families. Otherwise diagnose fitter/correctness-head mismatch or false-attractive fit before increasing exposure. No uncertainty calibration, GUI promotion, or DeepSlice benchmark is authorized by this diagnostic.
