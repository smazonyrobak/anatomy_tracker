# 128 design: teach the matcher that actually chooses the plane

The frozen [127 capture diagnostic](JOINT_POSE_CAPTURE_127_PROTOCOL_20261010.md) isolates a selection problem on the reused synthetic DEV plans: of 241 eligible sections, the current blind-16 beam contains a mapped candidate within 1.5 mm in 170, but the 122 selector chooses one in only 67. Exhaustively checking all 160 original branches raises availability to 188, a 7.47-percentage-point beam gain below the predeclared 10-point materiality threshold. Best blind-16 mapped error is 1.356 mm, while selected error is 3.364 mm. In all 241 cases the chosen blind action retains the prior top-1 branch; a prior top-3 branch is near in 137 cases. On this panel, larger beam search alone cannot close the gap; the inference matcher is barely changing the prior's branch choice. These values are synthetic development evidence, not physical-slide accuracy.

The 122 model already has a global image–atlas matcher. It renders a nine-point finite-thickness atlas plane for each blind candidate, compares 24×24 source and atlas features by cross-attention, and predicts a pose update and a score. However, its dense correspondence cross-entropy trains the separate `WholeSliceAtlasFeedback083` image/atlas towers. That auxiliary module is not used by the global matcher at inference. The 125 experiment instead trained an additional 32×32 dense ranker while freezing the 122 matcher and pose/map model. Its full-intensity pair decisions improved over support-only on some blind pairs, but selected mapped error improved only 0.011 mm over frozen 122; its gate failed. Repeating either extra head without changing the inference pathway is not justified.

The new treatment therefore supervises the **existing global matcher's own attention logits**. No model parameter, branch count, inference input, or default selector changes. A new 128-only forward function mirrors frozen `global_plane_matcher_120.py` exactly and exposes its pre-softmax 576×576 query/key logits, 24×24 rendered atlas support and atlas midplane CCF coordinates for the additional TRAIN loss. Both matched arms use this same forward function, so any treatment effect is attributable to the loss rather than a code-path change. The frozen 120 source and its 122/125 SHA-bound receipts remain untouched.

For each independently drawn synthetic TRAIN section, the known image-pixel-to-CCF centre field and intact-pixel validity are label sources only. The candidate states for correspondence teaching are (1) the synthetic observed-image affine gauge and (2) the minimum-error **original predicted blind-beam** branch, only if its rigid tissue-coordinate cost is ≤1.5 mm. The second case is training-only hard-positive selection; neither synthetic state, truth cost, nor validity mask is provided to the blind inference path. We keep the existing 122 physical-action listwise objective on all blind branches, including hard wrong planes, in both arms. There is no forced correspondence label for a wrong plane or a missing atlas location.

For a 24×24 query centre, bilinearly sample the known CCF centre field and require at least 95% intact synthetic validity over its source footprint. Orthogonally project that CCF point into the candidate plane's physical in-plane basis, accounting for reflection and pixel-centre convention. Let its projected atlas coordinate fall between four 24×24 key centres; assign bilinear probability to those keys rather than rounding to one. A query contributes only if all four key indices lie inside the rendered grid, their interpolated atlas support is ≥0.8, and the CCF point's absolute normal offset from the candidate midplane is no greater than that sample's rendered PSF half-width plus 12.5 µm (half one 25-µm atlas voxel). This normal gate matters: a synthetic image samples a deformed 3-D slab, so projecting an off-slab tissue point onto a single 2-D atlas render would produce a confident but physically false target. The central coordinate is still only an approximation to the source's complete through-plane integration; the loss is restricted to these defensible interior, near-slab sites and its eligibility fraction is reported. If no site qualifies, this auxiliary loss is zero for that section, never redrawn to cherry-pick geometry.

Cross-entropy is averaged over qualifying sites per candidate and then over available positive candidates; the provisional fixed treatment weight is 0.05 relative to the unchanged 122 objective. **Before finalizing that loss or trainer**, quantify the exact proposed mask on about 100 independent synthetic TRAIN sections: intact-query coverage, projected in-grid/support/normal eligibility, sections with any target, and the optional predicted-positive contribution. If the strict finite-PSF gate is sparse, do not loosen it based on DEV outcomes; revise the physically valid target design before training, potentially adding explicit through-plane classes. A one-batch TRAIN-only audit must then establish finite, nonzero gradients in the matcher's source and atlas towers and shared encoder, without dominating the base gradient. Gradient into the direct pose head is reported separately: the teacher-forced candidate cannot provide it, whereas an eligible predicted candidate may. Mere gradient connectivity is not evidence of improved coordinate inference. Existing 083 supervision remains in both arms. The 122 fit-difficulty term is disabled in both because its physical ranking was adverse and 125 did not qualify as replacement feedback.

This is one matched mechanistic test, not a claim that dense correspondence solves real tissue deformation. The 24-grid spacing is coarse relative to small nuclei; source texture is synthetic and atlas-derived; many peripheral, damaged or through-plane-warped cells must abstain. A negative result would not prove arbitrary planes impossible. A positive synthetic selection result would justify investigating a *separately validated* fitted-anatomy-to-direct-pose objective; it would not itself establish calibrated electrode probabilities, acquired steep-oblique generalization, DeepSlice superiority or GUI readiness.
