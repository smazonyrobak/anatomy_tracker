# Oriented 2D atlas-patch matching 025 — preregistered component gate

024 failed global 2D-patch/3D-cube retrieval (1.872% recall@16 within 0.5 mm against an atlas bank that covered 100% of query points within 0.25 mm). This is not evidence that atlas patch matching cannot work: [SLIV-Reg](https://arxiv.org/html/2410.18683v1) searches many *oriented 2D planes* through the volume and matches their 2D features; 024 instead crushed all orientation information into one 3D cube descriptor. [CoMIR](https://papers.nips.cc/paper/2020/hash/d6428eecbe0f7dff83fc607c5044b2b9-Abstract.html) motivates separate input stems for different image contrasts in a shared 2D representation.

025 tests the necessary cross-contrast matching step **without pretending the plane is already known at inference**. Render finite-thickness atlas images through each fresh synthetic TRAIN section's known CCF surface/pose (only training truth), in observed pixel coordinates; extract observed and atlas 64×64 patches centered on 32 independently drawn surviving tissue points per section. Use two modality stems followed by one shared, scratch-initialized 2D descriptor trunk. Train 3,000 batches × two fresh sections; each query sees the 64 corresponding atlas positives in its batch and 64 additional atlas negatives, with near-coordinate false negatives masked. Use the existing independently randomized arbitrary-plane/background/artifact generator, including raw, exact-black and imperfect-brush inputs. Save weights, optimizer and RNG at 0/1,000/2,000/3,000; keep exact source/animal/specimen/experiment/draw provenance.

On the same untouched 185-section synthetic DEV panel, sample 32 fixed GT-valid query points per section. The **diagnostic-only oracle plane** provides a 16×16 grid of atlas patch centers plus 32 exact positive patch centers. Thus each 288-item search has a true point; compare descriptors and report identity-equal point recall@1 and @16 within 0.25/0.5/1 mm, exact-positive rank, and per-mode results. Predeclared necessary gate: best nonzero checkpoint ≥25% recall@1 and ≥70% recall@16 within 0.5 mm, with no mode below half of overall recall@16. Failing this gate means the modality/appearance descriptor is unfit; do not spend effort on a 100,000-point × many-orientation atlas bank. Passing it only licenses the global-orientation/pose-consensus stage, **not** a claim of localization, nonrigid accuracy, real-data generalization, calibrated uncertainty or GUI readiness. Public benchmark and final-test animals stay sealed.
