# Off-plane capture 026 — fixed read-only diagnostic

025 learned reliable cross-contrast patch matching only when the **ground-truth deformed atlas surface** was supplied. The next necessary test removes that oracle surface. Freeze the 025 batch-3,000 descriptor and 019 batch-18,000 pose model. For every eligible section in the same 185-section synthetic DEV panel, render normalized finite-thickness atlas images at (a) the true **rigid affine** section plane, which excludes its known local warp, and (b) each of the frozen pose model's prior-top-eight rigid proposals. No weights are updated and no public benchmark or final-test animals are touched.

Select the same 32 fixed GT-valid query points as 025, solely to make this component diagnosis comparable; use a 16×16 regular atlas-patch grid plus the 32 query pixel locations in every candidate render. Score a plane by the mean best patch cosine within 64 image pixels of each query point, a truth-free local geometric-consistency window. Report separately: true-rigid point recall@1/@16 within 0.5 mm; fraction of cases where the true-rigid plane scores above all eight predictions; per-case **Spearman** correlation of the eight scores with negative physical rigid error; and identity-equal rigid error after selecting the highest-scoring predicted plane, versus the prior-selected and best-of-eight errors. Also report the matched atlas-point coordinate error, since choosing a plane and choosing correspondence within it are distinct problems.

Useful evidence for a capture basin would be ≥75% true-rigid wins, positive mean score/error association, and ≥0.25 mm reduction in selected rigid error versus the unmodified image prior, without mode-specific collapse. If these fail, the descriptor's oracle-plane success must not be promoted to unknown-plane registration; investigate orientation/translation search or feature invariance before joint pose training. If they pass, implement fit feedback and test final mapped error, not just this component score. Either outcome leaves real-animal validation, calibration, GUI replacement and fair DeepSlice comparison downstream.
