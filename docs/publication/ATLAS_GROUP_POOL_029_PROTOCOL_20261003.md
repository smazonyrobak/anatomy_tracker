# Rotation-group pooling 029 — frozen 025 representation test

027 found that 025's point descriptor tolerates normal tilt better than in-plane roll. 028 independently augments atlas-patch roll during scratch training. A second, read-only way to avoid storing many roll variants is to average each modality's 025 descriptor over a finite group of rotated versions of the *same* patch, then normalize. The atlas bank can store one pooled descriptor per 3D point and normal; the query is pooled once. This is rotation **invariance**, not the equivariant architecture of [SLIV-Reg](https://arxiv.org/html/2410.18683v1), and may discard discriminative structure.

Freeze 025 batch 3,000. On the same 185 disjoint synthetic DEV sections and 32 fixed query points, use the **known deformed atlas surface** and 288-patch bank from 025. Compare four 90° rotations and twelve 30° rotations, averaging normalized per-rotation features separately for query and atlas before a final normalization. For each group, also shift all atlas rotations by half a group step (45° or 15°) while leaving query rotations fixed, a worst-interpolation test. Report identity-equal top-1/top-16 point recall within 0.5 mm and per-mode results alongside the frozen unpooled 025 baseline. This is still an oracle-plane component diagnostic.

Group pooling is worth carrying into a coarse global atlas bank only if 12-rotation top-1 recall stays ≥80% within 0.5 mm, its half-step-shifted recall falls by ≤10 percentage points, and no raw/black/brush mode falls below half the overall rate. Otherwise choose the independently trained 028 representation if it passes its separate gate, or use explicit roll bins / proper group-equivariant features. No unknown-plane, real-animal, uncertainty, GUI or DeepSlice claim follows from passing.
